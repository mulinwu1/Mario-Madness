# 手动验证步骤（需要真实窗口的部分）

工装能自动比对的只有「离屏渲染 → 像素」这一段。下面这些**必须**用真实窗口跑，
脚本 `scripts/manual_window_check.ps1` 会把这份清单打印出来，可选地帮你启动游戏。

判定口径：每一项都写了「预期现在是什么」和「修好之后应该是什么」。现在的预期是按
README「已发现的问题」推出来的——如果实测和这里写的方向不一致，说明情况变了，回头补工装。

## 0. 前置

- 用仓库里 Vulkan 后端可用的构建（`native_vulkan/` 的渲染器接进 Lime 之后产出的 exe）。
- 确认进程能创建窗口（非 headless）。
- 打开日志窗口/控制台，后续要 grep。

## 1. 是否真的每帧都在画（对应问题 2）

步骤：启动游戏，进入任意关卡，让画面连续动 5 秒。

- **预期现在**：第一帧之后画面不再更新（或大部分帧是黑的/停住），因为
  `VkRenderer::EndFrame` 从不重置命令缓冲，第二帧起 `vkBeginCommandBuffer` 失败且被忽略。
- **修好后**：画面连续流畅更新；日志里每帧都有提交。
- 辅助判断：用 `scripts\perf.ps1` 跑 bench，`present` 等于 `frames` 但画面不动 = 命中此问题。

## 2. 画面上下方向（对应问题 1）

步骤：进入关卡，观察精灵/文字/HUD 的上下位置。

- **预期现在**：整帧上下颠倒（天空在地面下方、文字倒置或位置翻过来）。
- **修好后**：方向与 GL/ANGLE 参考一致。
- 注意：工装里 `01_clear` 是纯色，翻转看不出来，所以它 PASS 不代表方向对。

## 3. scissor 裁剪（对应问题 3）

步骤：找一个会用到裁剪的界面（HUD 滚动区域、对话框文字裁剪、小地图）。

- **预期现在**：内容溢出裁剪区域，整块都画出来（`lime_gl_scissor` 只记录了状态，没有下发）。
- **修好后**：超出部分被裁掉，边缘干净。

## 4. 半透明 sprite 叠加顺序（对应问题 3 + 5）

步骤：找同一帧里既有半透明特效、又有不透明精灵的画面（爆炸、烟雾、UI 遮罩）。

- **预期现在**：
  - blend 开关/混合公式没生效（`lime_gl_enable` / `lime_gl_blend_func` 不下发）；
  - 跨纹理的绘制顺序被按纹理槽重排（`EndFrame` 按 `textures` 顺序批处理）。
    → 叠加结果与美术预期不同，可能出现「后画的不透明块被半透明圆盘盖住」。
- **修好后**：叠加顺序与 alpha 混合都符合 GL 语义。
- 工装对应场景：`06_blend_overlay`。

## 5. 离屏 RT（对应问题 4）

步骤：触发一次离屏渲染管线（后处理、阴影图、缩略图）。

- **预期现在**：离屏内容丢失或串到主画面上，因为 `lime_gl_clear` 在离屏目标上会退回
  「直接开一帧到后缓冲」，把当前目标换掉。
- **修好后**：离屏 pass 的结果与主画面合成正确。
- 工装对应场景：`05_offscreen_rt`、`08_clear_routing`。

## 6. resize / 全屏

步骤：拖动窗口改变大小；按 Alt+Enter 切全屏再切回。

- **预期现在**：未知（工装不覆盖）。若出现花屏/黑屏，重点看 swapchain 重建与
  `CreateRenderTarget` 尺寸是否跟着更新。
- **修好后**：画面按新尺寸重绘，不拉伸不黑屏。
- 记录：注意日志里 present 是否连续、是否报 `LastError`。

## 7. 记录方式

每次手动验证后，把下面三样贴进 issue/PR：

1. 现象（截图或一句话）；
2. `out/perf.log` 里的 `GVD_PERF` 行（同一次运行的基线）；
3. 对应的工装场景结论（`out/report.md` 的汇总表）。

这样「手动看到的现象」和「自动比对的像素差」就能对上。
